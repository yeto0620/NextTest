# NextTest 小白可理解性改造指南

版本：v1.0
适用范围：NextTest 本地 Web 工作台（研究模式与科普模式）
目标用户：第一次接触材料实验、机器学习或主动实验设计的观众、学生与评委

## 1. 产品的一句话定义

> NextTest 用已有实验数据，帮助用户选择下一组最值得验证的方案。用户先锁定模型预测，再查看一条历史结果，观察新证据如何改变下一步。

界面中的任何模块、术语或操作都必须能够回到这句话。无法支持这条主线的信息，应折叠到“研究详情”或审计区域。

## 2. 全站唯一主流程

```text
看数据 → 比方案 → 锁预测 → 看结果
```

### 看数据

- 告诉用户当前数据描述什么、目标是什么、共有多少条已知记录。
- 明确当前是历史回放，不会执行真实物理实验。
- 原始 SHA、切分 SHA、内部路径默认不占据视觉主位。

### 比方案

- 默认只呈现方案、预测值、模型分歧、推荐原因和操作。
- “模型分歧”必须解释为模型意见不一致程度，不得称为概率、风险或置信度。
- 内部行号只作为次级标识，不作为方案名称的主体。

### 锁预测

- 按钮统一使用“锁定预测”。
- 锁定后必须解释：预测已经保存，系统不能根据答案反向修改预测。
- 预算必须说明为“最多查看几条历史实验结果”，不得暗示真实实验次数。

### 看结果

- 按钮统一使用“查看历史结果”。
- 结果区按“封存预测 → 历史结果 → 误差 → 判断更新”显示。
- 每轮结束必须出现“本轮完成”，并提供“查看本轮总结”和“继续下一轮”。

## 3. 首次使用规则

1. 研究模式仍可作为默认入口，但首次进入必须先给出产品的一句话定义。
2. 新手引导控制在五屏以内，每屏只讲一个动作。
3. 引导不得先介绍 SHA、数据闸门、独立留出等审计词汇。
4. 全站始终展示四步轨道，并标出当前所在位置。
5. 用户关闭引导后，仍能从顶栏重新打开。

## 4. 信息分层

### 第一层：任何人都必须看到

- 当前问题
- 当前推荐
- 推荐理由
- 下一步操作
- 本轮结果
- 科学边界

### 第二层：需要时展开

- 完整配方参数
- 模型名称与版本
- 项目编号
- 训练行数变化
- 数据切分与审计状态

### 第三层：研究核查

- 完整 SHA
- 事件链
- 冻结协议
- 内部状态码
- 只读审计字段

研究模式不是把所有字段同时铺开，而是允许用户逐层进入第二、第三层。

## 5. 统一词汇

| 禁止混用 | 统一界面用语 | 白话解释 |
|---|---|---|
| 公布 / 释放 / reveal | 查看历史结果 | 打开一条过去已经完成的实验记录 |
| 预测差值异 / 差异 | 模型分歧 | 多个模型对同一方案意见有多不一致 |
| freeze / 封存项目 | 锁定预测 | 先保存预测，之后不能根据答案修改 |
| historical replay | 历史回放 | 用过去的实验模拟一次选择与验证 |
| target hidden | 结果未查看 | 锁定预测前，历史结果不会进入浏览器 |
| budget | 查看次数 | 本轮最多可查看多少条历史结果 |

SHA、split、audit 等词只放在研究详情，并提供悬停或展开解释。

## 6. 状态必须自洽

- 未创建项目时，不得显示“预测已保存”。
- 自动选中的预览方案必须标记为“系统预览”，不得伪装成用户决定。
- 锁定后应明确说明为什么策略、目标和预算不可修改。
- 查看结果后必须明确说明本轮已经完成。
- 发生失败时必须给出下一步，不只显示内部错误名。

## 7. 助手与离线帮助

- 本地术语解释和流程导航不依赖 DeepSeek Key。
- DeepSeek 只负责解释公开证据，不参与推荐、选点或读取隐藏结果。
- 未配置 Key 时，AI 助手入口仍可打开本地帮助，不得直接置灰。
- 所有助手回答必须显示“解释，不是新增科研证据”。

## 8. 验收标准

让一名没有材料、机器学习背景的用户在不阅读外部文档的情况下：

1. 15 秒内说出平台是做什么的；
2. 30 秒内指出下一步应该点哪里；
3. 能解释“模型分歧不是置信度”；
4. 能独立完成一轮“锁定预测—查看历史结果”；
5. 能判断一轮何时完成；
6. 不会把历史回放误认为新物理实验；
7. 不会把模型预测误认为实验测量。

## 9. 改造顺序

### 第一轮：理解主线

- 一句话定位
- 四步轨道
- 五屏新手引导
- 预算与模型分歧白话解释
- 助手离线可进入
- 本轮完成状态

### 第二轮：模式分工（已实施）

- 研究模式默认开启，采用紧凑仪器台：表格优先、完整字段、证据账本、技术详情按需展开。
- 科普模式采用解释型导览：图形优先、问题解释、个人预判、结果反思。
- 两种模式共享同一数据、项目、选择和科研事实，不生成两套结论。
- 四步导航在研究模式显示“数据 / 方案 / 封存 / 证据”，在科普模式显示“看数据 / 比方案 / 锁预测 / 看结果”。
- 页面切换只改变表达和交互密度，不改变模型、候选排序、阈值或历史结果。

### 第三轮：研究首页减法（已实施）

- 首屏只保留当前任务、观测图、A/B 候选对照和一个主操作。
- 训练数、候选数、已查看数压缩为一行状态，不再铺设 KPI 卡片。
- 候选对照只显示方案 ID、预测、模型分歧、预测差和参数差；完整配方进入“完整方案”。
- 策略、证据、档案、数据、助手与只读恢复统一收入“更多工具”。
- 历史回放和预测边界保留在首屏，不因界面减法而隐藏。
- 主操作会随状态显示“锁定下一实验 / 进入实验 / 查看已锁预测 / 继续下一轮”。

### 第四轮：表格与失败状态（已实施）

- 研究表格默认只显示前三个关键控制量、预测、模型分歧和状态。
- 全部控制量仍可通过“展开全部”查看，选中行继续显示完整配方。
- 空方案不再只写“不可用”，而是引导用户检查数据字段与质量闸门。
- 全局错误统一显示“发生了什么、为什么没有完成、下一步做什么”。
- 写入状态不确定时只提供只读恢复或只读刷新，不提供自动重试。

### 第五轮：可用性验证

- 5 名零背景用户走查
- 记录首次完成时间、求助次数和术语误解
- 只修复反复出现的问题，不继续堆叠功能
